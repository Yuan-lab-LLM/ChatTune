# 管理员指南

本文说明 Studio 中的管理员操作流程。

## 首次初始化顺序

浏览器打开 `STUDIO_PUBLIC_URL`，使用管理员账号及runtime.env中生成的密码登录。

首次登录后，建议按以下顺序配置资源：

1. 创建普通用户。
2. 创建用户组，并为用户组绑定 Runtime 节点。
3. 为用户组配置训练、评测/推理和 GRPO 容器。
4. 把普通用户移动到已经配置好的用户组。
5. 创建 GPU 资源池。
6. 添加资源池节点和用户组配额。
7. 确认资源池已启用，用户组已有可用配额。

普通用户所在用户组必须同时具备 Runtime 节点、任务容器和 GPU 配额，才能稳定运行 Agent 任务。

## 用户管理

管理员可以：

- 创建用户，填写用户名、初始密码和角色。
- 按用户名、角色、用户组和在线状态搜索筛选。
- 移动普通用户到其他用户组。
- 启用或禁用账号。
- 重置密码并撤销会话。
- 在确认无影响后删除用户。

生产部署建议保留至少两个具名管理员账号。初始管理员账号只用于初始化和应急恢复。

## 用户组和 Docker 容器

每个普通用户组需要配置：

- 该组使用的 Runtime 节点。
- 训练容器。
- 评测/推理容器。
- GRPO/verl 训练容器。
- 保存后重新校验容器是否存在且可访问。

同一个 Runtime 节点内，不同用户组不应绑定同一个容器。不同 Runtime 节点可以使用相同容器名，但这些容器应彼此独立。

## GPU 资源池

在 GPU 资源页签中：

1. 创建资源池。
2. 添加资源池节点。
3. 配置每个节点的 `sshAlias`、`trainAddress`、允许 GPU 索引和可选 `ncclSocketIfname`。
4. 配置用户组配额：归属节点、保底 GPU 数、最大 GPU 数、最大并发任务数和单任务最大节点数。
5. 查看预约列表，处理过期或异常预约。

禁用资源池会阻止新预约，但不会中断已经运行的任务。存在 `preparing`、`reserved` 或 `running` 状态预约时，相关资源池和配额配置会被锁定。

## 共享和审计

- 共享页签用于审批或拒绝用户提交的资源发布申请，也可以由管理员直接发布私有资源。
- 发布前应确认数据、模型、日志和输出不含个人信息、受限数据或密钥。
- 审计页签记录用户、用户组、资源池、共享和审批相关管理员操作。建议按部署要求备份数据库并导出审计记录。
